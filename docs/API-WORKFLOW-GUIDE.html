1. Client Sends A Request

A client can be a browser, frontend application, curl, Postman, another backend service, or a Kubernetes health probe.

GET  /health
GET  /ready
POST /ask

For POST /ask:

{
  "question": "What is Kubernetes?"
}

2. Uvicorn Receives The Request

Uvicorn is the web server process. It listens for HTTP requests and passes them to FastAPI.

\.\.venv\Scripts\python.exe -m uvicorn app.src.main:app --reload

app.src.main:app means app.src.main is app/src/main.py and app is the FastAPI variable inside it.

3. FastAPI Maps The Request To A Route

The current route definitions are in app/src/api/routes.py.

RequestHandlerPurpose
GET /healthhealth_check()Confirms the process is alive
GET /readyreadiness_check()Confirms the app is ready
POST /askask_question()Accepts a question and returns an answer
@router.get("/health")
def health_check():
    return {"status": "healthy"}

GET /health -> health_check()

The route is the public HTTP contract that points to the Python function.

GET  /health -> health_check()
GET  /ready  -> readiness_check()
POST /ask    -> ask_question()

Who Uses Each Endpoint?

Regular users normally do not call /health or /ready directly. They use the business endpoint:

User -> Frontend -> POST /ask -> FastAPI -> AI model

Kubernetes, load balancers, and monitoring systems use the health endpoints:

Kubernetes -> GET /health
Kubernetes -> GET /ready

/health: liveness check

GET /health answers: "Is the API process alive?" It should be a small and fast check. If it fails repeatedly, Kubernetes can restart the API container.

/health = restart me if the process is broken

/ready: readiness check

GET /ready answers: "Can this API safely receive traffic?" If it fails, Kubernetes keeps the pod running but temporarily removes it from Service traffic.

Later, this endpoint can check dependencies such as Ollama, a database, or AWS Bedrock:

/health -> 200 OK   (the process is alive)
/ready  -> 503      (a required dependency is unavailable)

This prevents users from being routed to a pod that is running but not able to complete requests.

7. Application Wiring

The route file creates an APIRouter, but the FastAPI application must include that router.

The FastAPI application is in app/src/main.py and already includes the router.

from fastapi import FastAPI
from .api.routes import router

app = FastAPI(title="Secure AI Platform API")
app.include_router(router)

include_router(router) connects the route definitions to the running application. Without it, the functions exist in Python but are not exposed as URLs.

routes.py
  -> router = APIRouter()
  -> @router.get(...) and @router.post(...)
  -> app/src/main.py imports router
  -> app.include_router(router)
  -> Uvicorn runs app.src.main:app
  -> clients call the URLs

Useful URLs:

http://localhost:8000/health
http://localhost:8000/ready
http://localhost:8000/docs

Automated Testing

Manual browser or PowerShell checks are useful, but repeating them after every code change is inefficient. Automated tests check the API consistently before Docker or Kubernetes deployment.

The tests verify /health, /ready, valid and invalid /ask requests, and the response structure. This is called shift-left testing: find problems early, before deployment.

Without tests: Code change -> Docker image -> Kubernetes deployment -> failure discovered late
With tests:    Code change -> test detects problem -> pipeline stops

The tests are in app/tests/test_api.py. They use FastAPI's TestClient, which loads the application directly in memory instead of using a network port.

TestWhat it protects
test_health_endpoint/health returns 200 and healthy status
test_readiness_endpoint/ready returns 200 and ready status
test_ask_endpoint_with_valid_questionValid question returns an answer
test_ask_endpoint_removes_extra_spacesSurrounding spaces are cleaned
Invalid-input testsBlank, missing, or wrong-type questions return 422

Tests follow three stages:

Arrange -> prepare request data
Act     -> call the endpoint
Assert  -> check the result
request_body = {"question": "What is the policy?"}
response = client.post("/ask", json=request_body)
assert response.status_code == 200
assert response.json()["answer"]

Stop Uvicorn with Ctrl+C if it is running. From the repository root, with (.venv) active, run:

python -m pytest .\app\tests -v

Expected result:

7 passed

Uvicorn is not required because TestClient(app) calls FastAPI directly in the test process. The workflow is:

FastAPI code -> pytest -> Docker image -> Kubernetes deployment
